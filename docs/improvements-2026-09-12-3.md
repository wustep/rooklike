# Proposed Improvements — rooklike — 2026-09-12 (round 4, final sweep)

## Technical

### 1. The engine scores a draw as 0, so a losing enemy steers into repetition
- **Impact:** 🔴 high · **Effort:** S · **Status:** ❌ rejected
- **Problem.** `src/game.ts:159` ends the run on any `chess.isDraw()`, so a draw is a full win for the enemy, but the search returns `0` for draws at `src/engine.ts:81`, `:91`, `:102`, `:114`. Once black's eval is negative, `0` is its best score, so it shuffles into a third repetition. The worker searches the replayed game, so repetition is visible in-search.
- **Proposal.** `drawScore()` returning a side-relative penalty for the side that needs a win (ivory), roughly a minor piece, used at the four sites; add a repetition test.
- **Risks / trade-offs.** Too large a penalty makes a winning black avoid a fair repetition; keep it under a minor piece.
- **Files.** `src/engine.ts`, `tests/engine.test.ts`

### 2. Takeback charges are stranded by a page reload
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** History lives only in React state (`src/App.tsx:23`); the save effect persists `run` alone. After a reload mid-battle the button is disabled while still showing charges. Not reconstructible from SAN (coins, army, bonuses).
- **Proposal.** Persist history under `rooklike-history-v1`, capped to ~12 snapshots, loaded only when stage/seed/moves length match the run.
- **Risks / trade-offs.** Quota; reuse the existing save-error path.
- **Files.** `src/App.tsx`, `src/game.ts`, `tests/game.test.ts`

## UI/UX & Design

### 3. The short-desktop board reserve no longer fits the panel
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `src/style.css:96` sizes the board as `calc(100dvh - 220px)`; the briefing and material strip added ~66px, so at 1440×900 the board tools fall below the fold. Two earlier `.battle-panel` declarations at `:11` and `:47` are dead.
- **Proposal.** Raise the reserve to ~300px; delete the two dead declarations.
- **Risks / trade-offs.** Smaller board on short windows.
- **Files.** `src/style.css`

### 4. Three live regions fire on one enemy ply
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** The whole turn bar is the region (`src/App.tsx:173`), so the visible "Enemy thinking…" flip and turn count announce alongside the `sr-only` sentence; the material strip adds a third `role="status"` (`:196`).
- **Proposal.** Live region on the `sr-only` span only; `aria-hidden` the visible bar text and the strip; append the material reading to the announcement after a capture.
- **Risks / trade-offs.** Region must stay mounted.
- **Files.** `src/App.tsx`

### 5. New elements reintroduce the retired contrast tier
- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** Briefing lesson `#7d8a76` (`style.css:114`, `:120`) and material strip base `#7d8a76` (`:122`); ~3.7:1 over themed centre gradients.
- **Proposal.** Lift both to `#95a488`.
- **Risks / trade-offs.** Flatter hierarchy; italic still separates the lesson.
- **Files.** `src/style.css`

### 6. Material strip pops in mid-battle and breaks the gutter
- **Impact:** 🟡 med · **Effort:** S · **Status:** ✅ accepted
- **Problem.** Renders only after the first capture, inserting ~31px under the cursor; no horizontal margin while neighbours use 4-5px.
- **Proposal.** Always render with a min-height and the same gutter.
- **Risks / trade-offs.** Empty row costs height at 390px.
- **Files.** `src/App.tsx`, `src/style.css`

## Product Features

### 7. Relic and monster effects fire silently into a collapsed journal
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** All economy events (`game.ts:129-131`, `:136`, `:140-142`) go only to `run.log`; the journal starts closed. Four relics and all four monster abilities pay or tax with no on-screen feedback (BRIEF: effects "always readable in UI"). `supply` never shows at all in the shop.
- **Proposal.** Effect on `run.log` length: any new non-move entry goes through `setNotice` (joined, capped at two); strike the base cost in the shop when `supply` is held.
- **Risks / trade-offs.** Notice spam on a busy ply; cap and join.
- **Files.** `src/App.tsx`

### 8. A draw ends the run with the wrong explanation
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** The end modal (`App.tsx:230`) prints one stalemate-specific line for every draw; repetition, 50-move and insufficient material are all reachable.
- **Proposal.** `drawReason(chess)` in `game.ts` with a reason and one teaching line per kind; render in the end modal.
- **Risks / trade-offs.** None; pure and testable.
- **Files.** `src/game.ts`, `src/App.tsx`, `tests/game.test.ts`

### 9. The intro modal never shows a first-time player how to move
- **Impact:** 🟡 med · **Effort:** S · **Status:** 🕓 deferred
- **Problem.** The field guide is unreachable from the intro (`help&&!intro`, `?` handler returns early while `intro`); the input sentence lives only inside it.
- **Proposal.** Add the input sentence to the intro plus a quiet "New to chess? Read the field guide" button.
- **Risks / trade-offs.** Competes with Begin; keep it quiet.
- **Files.** `src/App.tsx`, `src/style.css`

### 10. `Encounter.description` is dead data
- **Impact:** 🟡 med · **Effort:** S · **Status:** ❌ rejected
- **Problem.** Authored for all 21 configs, rendered nowhere.
- **Proposal.** Show as the sub-line of the encounter heading above the briefing; clamp to one line.
- **Risks / trade-offs.** A third line above the board at 390px; conflicts with 3.
- **Files.** `src/game.ts`, `src/App.tsx`, `src/style.css`

## DevEx

### 11. CI never runs `npm run build`
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** `ci.yml` runs typecheck, vitest, Playwright but not the Rollup bundle; Vercel's deploy is the only place the worker bundle and the DEV branch are verified.
- **Proposal.** Add `npm run build` after typecheck.
- **Risks / trade-offs.** ~15s.
- **Files.** `.github/workflows/ci.yml`

### 12. Playwright browsers re-downloaded every CI run
- **Impact:** 🟡 med · **Effort:** S · **Status:** 🕓 deferred
- **Problem.** `npx playwright install --with-deps chromium` unconditionally.
- **Proposal.** Cache `~/.cache/ms-playwright` keyed by the Playwright version.
- **Risks / trade-offs.** Stale cache on a bump; the key handles it.
- **Files.** `.github/workflows/ci.yml`

### 13. Every e2e spec but one pays full search plus the 550ms delay
- **Impact:** 🟡 med · **Effort:** S · **Status:** 🕓 deferred
- **Problem.** Only the act spec injects the DEV hook; every other enemy reply runs the production profile behind the delay.
- **Proposal.** Apply the hook in a shared `beforeEach`/fixture; specs asserting move quality opt out.
- **Risks / trade-offs.** Weaker replies where a spec relies on them.
- **Files.** `e2e/*.spec.ts`, `playwright.config.ts`

### 14. `cancel-in-progress` kills main's run on back-to-back merges
- **Impact:** 🔴 high · **Effort:** S · **Status:** ✅ accepted
- **Problem.** The concurrency group is per ref, so a second merge cancels the first commit's run (observed today: #13 and #14 runs cancelled).
- **Proposal.** `cancel-in-progress: ${{ github.event_name == 'pull_request' }}`.
- **Risks / trade-offs.** Main runs queue.
- **Files.** `.github/workflows/ci.yml`
